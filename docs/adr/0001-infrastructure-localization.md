# ADR 0001. Локализация инфраструктуры в РФ

- **Статус:** Accepted (рабочая гипотеза до закрытия открытого вопроса B.6)
- **Дата:** 2026-08-27
- **Связанные требования:** FZ-01.1, FZ-01.6, FZ-09, открытый вопрос B.6

## Контекст
580-ФЗ требует физического размещения серверов, БД, резервных копий и журналов
на территории РФ. Выбор конкретного оператора ЦОД — юридическое решение (B.6).

## Решение
1. Целевая зона по умолчанию — `ru-central-1` (совместима с Yandex Cloud Object Storage
   и AWS SDK). Все значения регионов в репозитории указывают на РФ, а не на `us-*`/`eu-*`.
2. Terraform разделён на два слоя:
   - `infra/terraform` — деплой приложения в уже существующий Kubernetes;
   - `infra/terraform/yandex` — описание кластера, управляемой PostgreSQL, объектного
     хранилища, реестра образов и сети в российской зоне. Провайдер можно заменить
     на Selectel / VK Cloud без изменения приложения: зона задаётся переменной `cloud_region`.
3. Резервные копии, реплики БД и логи размещаются в той же зоне (`backup_region = ru-central-1`).
4. Реестр фактических площадок ведётся в системе (`placement_sites`) и в
   `infra/placement/inventory.yaml`.

## Последствия
- `terraform apply` в каталоге `yandex` создаёт инфраструктуру только после выдачи
  учётных данных выбранного оператора.
- Смена оператора ЦОД = смена backend Terraform и переменных, без переписывания домена.
