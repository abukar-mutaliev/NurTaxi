# Восстановление из резервной копии (C3.4, FZ-03.4, FZ-08.17)

- **Периодичность проверки:** ежеквартально.
- **Зона хранения копий:** та же российская зона, что и основная площадка (`ru-central-1` / `infra/terraform/yandex`).
- **Состав:** управляемая PostgreSQL (окно бэкапа 03:00, 14 суток) + бакет `nurtaxi-backups-*` для дампов и объектного хранилища, бакет логов отдельно.
- **Шифрование:** средствами оператора ЦОД (диск кластера + SSE бакета).
- **Доступ:** отдельная роль `nurtaxi-backup-restore`, без прав на продуктовую запись.

## Процедура восстановления (staging)

1. Создать кластер из последней успешной копии (`yandex_mdb_postgresql_cluster` restore / PITR).
2. Прогнать `npm run migration:show:prod` — схема совпадает с HEAD.
3. Выборочно сверить 10 заказов и checksum журнала (`record_checksum`).
4. Восстановить бакет выгрузок, скачать контрольный файл, сверить SHA-256.
5. Зафиксировать акт в реестре площадок (`placement_site_logs`).

Пока `folder_id` не выдан (B.6), apply не создаёт кластер (`count = 0`); каркас готов.
